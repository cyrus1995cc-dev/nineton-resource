# Go 后端迁移与目录拆分

日期：2026-10-27。

## 结果与目录

- `frontend/`：Vue、页面组件、样式、前端共享规则、独立 npm 锁文件、Capacitor 安卓工程。
- `backend/`：Go HTTP 服务、MySQL 连接池、事务、迁移程序、业务测试。旧 Node/SQLite 实现移至 `backend/legacy-node/` 供核对，生产包不包含它。
- `deploy/`：Nginx、systemd、MySQL 小内存配置、环境变量示例、备份脚本和部署说明。
- `scripts/build-release.ps1`：在构建机生成 Linux amd64 / arm64 发布目录，使用 `CGO_ENABLED=0`，交付程序、静态网页和校验清单。服务器无需 Node.js、npm 或 Go 编译器。

API 保持 `/api` 路径及既有数据结构，覆盖登录/权限、资产查询编辑、二维码保留、流转审批、盘点、Excel `.xlsx` / `.xls` 导入和三类导出、钉钉通讯录/已有登录适配。

审批和归属变更在 MySQL 事务内执行；锁定单据、资产及相关身份，失败时整批回滚。台账显式增加版本号，保留导入预览归属/有效期/版本核对、重复确认、重复审批与重复扫码保护。搜索保留大小写不敏感的行为，唯一编码和旧二维码保持精确保存。

低内存起步参数：数据库连接池最多 8、Go 软内存目标 384 MiB、导入导出并行 1 个、登录密码计算并行 2 个；MySQL 缓冲池建议 256 MiB，systemd Go 进程硬上限 640 MiB。数据库与 Go 总 RSS 不能由这些参数直接相加推断。

## 本地验证

- 前端类型检查、16 项测试、生产构建通过；依赖审计未报告漏洞。
- Go 单元及 MySQL 8.4.10 集成测试通过，覆盖角色、会话撤销、同名员工隔离、顺序审批、幂等、审批原子回滚、并发最终审批、并发扫码、导入版本冲突/归属保护/过期、导出文字公式保留、`.xls` 读取、通讯录同步失败保留及授权范围缺失。
- 旧 Node 后端 51 项测试仍通过。
- 原 SQLite 以只读方式迁移到独立 MySQL 测试库：1762 条资产；逐项核对 ID、编码、二维码、状态、位置、人员及关联 ID、版本、金额、名称、型号、原业务日期等 17 个字段。资产状态为在用 1249、空闲 513。全部业务表数量与密码哈希核对通过。
- 另建历史数据样本验证审批、履历、评论、盘点、二维码别名和通知队列的迁移。迁移后待审批请求的幂等重放、继续审批通过；对非空目标库重复迁移被拒绝。旧会话不迁移。
- Chrome 桌面实际登录与资产列表通过，显示 20 条分页数据，无页面异常；390 × 844 手机宽度无横向溢出。
- 本机 Go + MySQL，真实 1762 条资产，8 并发混合查询 160 次无失败，P95 约 14.6 ms；资产 Excel 导出约 170 KB。该次验证 Go 工作集峰值约 51 MiB、MySQL 工作集约 531 MiB，属于 Windows 本地结果，不代表 Linux 或 2 核 2G 的容量承诺。
- 安卓目录调整、Capacitor 同步及 `assembleDebug` 编译通过（使用本机 Gradle 9.6.1）；Gradle Wrapper 的远程下载通道曾超时，已使用本机工具完成编译验证。正式 API 地址确认后还需重新构建和真机验证。
- Linux amd64 Go 服务与迁移工具交叉编译通过，发布目录附 SHA256 清单。
