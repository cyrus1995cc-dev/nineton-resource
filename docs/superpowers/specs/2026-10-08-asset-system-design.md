# 资产管理系统设计

**日期：** 2026-10-08  
**状态：** 方案已获用户确认，等待实施计划审核  
**范围：** Web 管理后台、Android App、钉钉 H5；iOS 和标签打印延期

## 1. 目标

建设一套由公司自己掌控的资产管理系统，使用公贝云导出的 Excel 作为初始数据和后续批量同步来源。系统需要兼容现有资产二维码：在自有 Android App 或钉钉 H5 中扫码时，把二维码内容当作字符串解析，不打开公贝云网址，并通过资产编码查询本地资产。

一期必须覆盖资产清单、资产详情、扫码查询、领用、归还、借出、调拨、维修、报废、盘点基础能力、操作记录、基础权限和数据统计。网页版的布局和信息密度参考用户提供的公贝云截图，但不复制其实现或依赖其接口。

## 2. 已确认约束

- 现有二维码内容是类似 `https://d.gongbeiyun.com/a/58b7d/57771/CSJ-0431` 的 URL 字符串。
- 公贝云接口不可用，系统只能通过 Excel 导出文件导入或更新数据。
- 当前资产清单包含 1,762 条记录、22 个字段，资产编码唯一。
- 手机端只做 Android；不开发 iOS。
- YLF-280 USB 标签打印暂不进入一期，仅预留数据字段和接口边界。
- 钉钉以 H5 微应用和企业身份接入为主，保留系统本地管理员登录作为兜底。

## 3. 产品范围

### 3.1 Web 管理后台

- 首页看板：资产总量、在用/空闲、分类、位置、公司、部门、金额等统计。
- 资产清单：搜索、筛选、排序、分页、列显示设置、批量操作、导入和导出。
- 资产详情：基础属性、二维码、照片、当前状态、当前使用人、流转时间线。
- 资产流转：领用、归还、借出、借出归还、变更使用人、调拨、维修、报废。
- 盘点：创建盘点任务、按位置或部门生成任务、记录盘点结果和差异。
- 基础资料：资产分类、位置、公司、部门、员工。
- 权限：管理员、资产管理员、部门负责人、普通员工等角色；按公司和部门限制数据范围。
- 设置：导入规则、二维码解析规则、字段显示设置和审计查询。

### 3.2 Android App

- 企业账号登录或钉钉入口登录。
- 相机扫码并保留二维码原文。
- 旧公贝云 QR、新系统 QR、直接资产编码三种输入兼容。
- 资产详情查看。
- 领用、归还、借出、归还确认、盘点等移动操作。
- 操作前显示资产和人员确认信息，操作后显示结果和最新状态。
- 首期需要联网；为后续离线盘点预留同步边界，不在一期实现完整离线同步。

### 3.3 钉钉 H5

- 在钉钉工作台打开移动端页面。
- 使用钉钉企业身份完成免登或 OAuth 登录。
- 将钉钉用户映射到系统员工。
- 使用钉钉内可用的扫码能力或 H5 摄像头能力。
- 发送领用、归还、盘点任务等通知。
- 钉钉审批先保留接口边界，二期实现具体审批表单和回调。

## 4. 推荐架构

采用模块化单体后端，避免一期拆分多个微服务造成部署和调试成本。所有客户端通过统一 HTTPS API 访问同一套业务模块。

```text
Web 管理后台 ───────┐
Android App ────────┼──> 统一后端 API ──> PostgreSQL
钉钉 H5 ────────────┘          │             ├─ 审计日志
                              └─────────────└─ 文件/照片存储
```

推荐技术栈：

- Web 和移动 H5：Vue 3、TypeScript、Vite、Element Plus、ECharts。
- Android：复用移动 H5，通过 Capacitor 打包 Android；扫码使用原生摄像头插件。
- 后端：Node.js、NestJS、TypeScript。
- 数据库：PostgreSQL。
- 缓存和任务：Redis，首期用于登录会话、导入任务和通知队列。
- 文件：S3 兼容对象存储；开发环境可用本地磁盘，生产环境使用对象存储。
- 部署：Docker Compose，反向代理使用 Nginx，所有客户端访问 HTTPS。

Capacitor 的选择让 Web、Android 和钉钉 H5 共享主要业务页面和状态模型；涉及摄像头、通知等能力时只通过小型原生适配层处理。

## 5. 核心数据模型

### 5.1 资产 `assets`

- `id`：系统内部 UUID。
- `asset_code`：资产编码，唯一，例如 `CSJ-0431`。
- `qr_raw`：最近一次导入或扫码得到的完整二维码字符串，可为空。
- `qr_format`：`gongbeiyun_url`、`native_url`、`asset_code`、`unknown`。
- `name`、`category_level1`、`category_path`、`status`。
- `location_id`、`company_id`、`department_id`、`assignee_employee_id`。
- `model`、`cpu`、`memory`、`gpu`、`serial_number`、`remark`。
- `purchase_amount_taxed`、`purchase_amount_untaxed`、`tax_amount`。
- `purchase_or_created_at`、`received_at`、`retired_at`。
- `photo_urls`：数组，允许后续补充多张照片。
- `source_updated_at`、`created_at`、`updated_at`。

### 5.2 流转事件 `asset_events`

保存领用、归还、借出、调拨、维修、报废和盘点差异等不可变事件：资产、事件类型、操作者、原状态、新状态、原人员、新人员、原位置、新位置、备注、附件和时间。

资产表保存当前快照，事件表保存完整历史；任何状态变化必须通过事件服务完成，禁止由客户端直接改状态字段。

### 5.3 导入批次 `import_batches`

保存上传人、文件名、文件校验值、字段映射、总行数、新增数、更新数、异常数、确认时间和错误明细。导入采用预览后确认，不直接覆盖生产数据。

### 5.4 身份和权限

- `employees`：系统员工，保存姓名、工号、公司、部门和钉钉身份标识。
- `departments`、`companies`、`locations`：组织和位置基础资料。
- `users`、`roles`、`permissions`、`user_scopes`：登录、角色和数据范围。
- `audit_logs`：登录、导入、查看敏感数据、流转、权限变化等审计记录。

## 6. 二维码解析规则

二维码扫描组件只返回字符串，不自动导航。解析器输入 `raw: string`，输出：

```ts
type ParsedQr = {
  raw: string;
  assetCode: string | null;
  format: 'gongbeiyun_url' | 'native_url' | 'asset_code' | 'unknown';
};
```

规则顺序：

1. 去除首尾空白。
2. 匹配已知公贝云路径，提取路径最后一段作为资产编码。
3. 匹配自有系统 URL，提取路径或查询参数中的资产编码。
4. 匹配资产编码格式，直接查询。
5. 未识别时保留原文并提示用户手动搜索。

公贝云二维码格式保存为可配置规则，不写死在页面。重印旧标签时使用保存的 `qr_raw`；如果历史导出没有原文，则使用已验证的公贝云前缀加资产编码生成候选值，并在批量重印前抽样验证。

## 7. Excel 导入流程

导入以“资产编码”为唯一匹配键，映射当前清单的 22 个字段。流程为：

1. 上传文件并计算校验值。
2. 读取表头，显示字段映射。
3. 校验编码为空、重复、状态值、日期和金额格式。
4. 生成新增、更新、空值覆盖和异常预览。
5. 用户确认后在事务中写入资产快照，并记录导入批次。
6. 对字段变化写入审计记录；不因 Excel 缺少某字段而删除系统已有照片、流转历史或二维码原文。

默认规则是不使用空值覆盖已有非空值；明确的删除或停用动作通过系统操作完成。导入不能物理删除资产。

## 8. API 边界

后端按领域划分模块，但一期部署为一个服务：

- `auth`：本地登录、钉钉登录、会话和员工绑定。
- `assets`：清单、详情、搜索、二维码查询。
- `asset-events`：领用、归还、借出、调拨、维修、报废。
- `imports`：上传、预览、确认、错误下载。
- `master-data`：公司、部门、员工、分类、位置。
- `inventory`：盘点任务、盘点记录、差异。
- `reports`：看板统计和导出。
- `notifications`：钉钉通知接口，首期允许异步失败重试。
- `print`：只定义任务接口和模板实体，不实现 YLF-280 驱动。

所有写操作需要幂等键或业务事件编号，避免移动端重复点击造成重复领用或归还。

## 9. 安全和审计

- 全部生产请求走 HTTPS。
- 密码只存哈希；钉钉身份只保存必要的稳定标识。
- 资产流转、导入、权限和敏感字段查看写入审计日志。
- 资产管理员可以操作资产；普通员工默认只能查看授权范围和发起本人相关操作。
- 所有批量导入和批量流转需要预览和确认。
- 附件上传限制大小、类型和访问权限。
- 接口按角色和数据范围校验，不能只依赖前端隐藏按钮。

## 10. 一期验收标准

1. 导入当前 Excel 后，系统显示 1,762 条资产，资产编码无重复。
2. 扫描 `CSJ-0431` 的旧二维码，在 Android App 和钉钉 H5 中都能打开本地资产详情，不跳转公贝云。
3. 对任一资产完成领用和归还后，当前状态、使用人和流转时间线同步更新。
4. 同一领用请求重复提交不会生成两条生效事件。
5. Web 清单可按编码、分类、状态、位置、公司、部门和使用人筛选。
6. 导入同一文件两次不会产生重复资产。
7. 空值导入不会删除已有照片、二维码原文和流转历史。
8. 管理员、资产管理员和普通员工看到的数据范围符合权限配置。
9. 钉钉用户能完成登录和员工绑定；钉钉不可用时本地管理员仍可登录。
10. 打印模块只验证接口预留，不在一期承诺 YLF-280 打印。

## 11. 非目标和风险

- 不通过接口实时同步公贝云；数据同步依赖人工导出和导入。
- 手机系统相机直接扫描仍会打开公贝云网址；只有自有 App 或钉钉 H5 能拦截并解析字符串。
- 当前 Excel 只提供一条资产照片 URL，照片迁移不能假设完整。
- 钉钉免登、通讯录、通知和审批取决于企业管理员配置的开放平台权限。
- 首期不做离线盘点、iOS、YLF-280 直连打印和复杂审批编排。
