## 2. 服务端凭证

本地私有文件 `.data/dingtalk-app.env` 供管理员填写，不进入 Git。文件读取权限限当前 Windows 用户和 SYSTEM。填写后由部署流程写入服务器 `/etc/asset-system.env`（root 0600），重启服务；密钥不放入前端，也不在日志中输出。

```ini
DINGTALK_CORP_ID=企业CorpId
DINGTALK_CLIENT_ID=应用ClientID或AppKey
DINGTALK_CLIENT_SECRET=应用ClientSecret或AppSecret
DINGTALK_AGENT_ID=应用AgentId
```

前三项用于免登和通讯录。AgentId 为后续待办 / 消息联调准备，当前程序尚无消息发送器，仅填写 AgentId 不会发送消息。前端配置接口仅返回启用状态、CorpId 和公开的 ClientId。

## 3. 程序已准备的免登链路

1. 钉钉客户端打开应用，前端按需加载打包在站点内的官方 `dingtalk-jsapi@3.2.9`，携带 CorpId 和 ClientId 调用 `requestAuthCode`。
2. 前端将一次性免登码交给 `/api/auth/dingtalk/login`；服务端用企业应用 accessToken 调用 `/topapi/v2/user/getuserinfo`，获取企业 userid。
3. 以服务端固定 CorpId 和钉钉返回的 userid 关联已经同步的员工。没有同步、停用或授权范围待核对的身份不能登录，不按姓名或钉钉管理员标记授予系统管理权限。
4. 建立本系统会话，保留通知链接中的 `?flow=单据ID`。普通浏览器仍使用本地维护账号；钉钉退出登录后不会立即再次自动登录。

SDK 授权有超时和失败提示。本次采用的新版 API 要求 Android/iOS 至少 7.0.45、Mac/Windows 至少 7.0.50；实际联调建议将测试人员钉钉更新到最新版本。

## 4. 真实企业验收顺序

1. 用现有管理员账号在普通浏览器登录九吨资产，进入“组织与人员 → 同步设置与记录”。
2. 首次先保持定时同步关闭；设置已授权的起始部门 ID，完整企业通常是 `1`，部分授权用实际可访问的部门编号。
3. 执行“立即同步”，核对部门层级、测试人员、工号和兼职部门。完整读取成功后才更新本地通讯录，失败保留原数据。
4. 如需按公司管理人员，在“公司管理 → 修改”中选择公司对应的钉钉部门；不把钉钉部门自动当作新公司。
5. 测试人员分别从手机和 PC 钉钉工作台进入应用，验证自动登录、“我的资产”和权限。默认员工角色，需要管理权限时由现有系统管理员手工分配。
6. 在“旧台账关联”核对姓名、部门、工号后逐项关联存量资产。不会自动把同名资产分配给钉钉员工；初次登录“我的资产”为空时先检查关联情况。
7. 验证通过后再配置周期同步和扩大应用范围。授权范围缩小会将未再读到的人员标记待核对并撤销关联会话，扩大或缩小范围前需核对影响。

本轮 28 项前端测试、类型检查、构建及专用 MySQL 测试库中的 Go 回归已通过。包括正确企业身份换码、其他企业拒绝、停用/范围缺失拒绝、同名隔离、角色保留及本地管理员入口。模拟测试不能代替企业应用真实免登、权限和设备验收。

## 5. 后续联动

审批任务使用钉钉待办，审批完成后更新待办状态；普通结果通知可用工作通知。资产审批规则和台账事务继续由九吨资产处理。官方“发送工作通知”明确将审批任务列为不适用场景，因此当前不会把队列中的审批提醒直接当作工作通知发送。下一阶段还需补充待办权限、创建 / 完成 / 撤销、重试去重与真实接收人验收。

应用内扫码、钉钉内 Excel 下载和普通浏览器钉钉扫码登录将分别接入、验收，不因免登测试通过而声称这些功能已完成。
