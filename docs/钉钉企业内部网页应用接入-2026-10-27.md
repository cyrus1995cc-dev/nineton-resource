# 钉钉企业内部网页应用接入

日期：2026-10-27。用户明确资产系统需要成为钉钉里的应用，按现有开发者平台应用的“网页应用”能力接入，覆盖移动端和 PC 端。正式数据库目标为 MySQL。

本文件是平台配置与改造说明。本轮没有修改钉钉企业后台、扩大应用权限、发布版本，也没有完成免登或数据库切换。

## 一、目标使用方式

员工在钉钉工作台打开“资产管理系统”，通过钉钉企业身份进入自己的资产、流转和盘点等有权使用的页面。手机在应用内部发起扫码，将二维码原文交给现有解析逻辑，保留旧标签。审批待办和结果以钉钉工作通知推送，点击后打开对应资产系统单据；审批规则和台账更新仍由资产系统处理。

钉钉平台登记应用入口、企业权限和发布范围；程序、接口、MySQL 和备份部署在公司的服务器上。企业内部网页应用通过网址提供服务，现有 Android APK 可作为另一访问入口，员工在钉钉内使用网页应用不依赖安装该 APK。

独立浏览器网页版保留，浏览器中的登录与钉钉客户端内免登按各自流程接入并验证。钉钉原生审批和原生待办是额外的接入能力，当前不能把资产系统自身审批或工作通知称为已经接通这些能力。

## 三、平台配置顺序

### 1. 凭证与基础信息

确认企业 CorpId、应用标识以及应用凭证。现有服务端配置使用 `DINGTALK_CORP_ID`、`DINGTALK_CLIENT_ID`（AppKey）、`DINGTALK_CLIENT_SECRET`（AppSecret）；消息发送接入时还需确认该应用对应 AgentId。AgentId 暂未接入发送代码。

AppSecret 由服务端保管，配置截图应遮住密钥。应用开发成员和员工可使用应用的范围是不同概念，不能仅添加开发成员就认为已经对员工发布。

### 2. 权限管理

按实际调用接口申请部门与员工读取、身份获取和工作通知发送所需权限，并配置通讯录授权范围。具体权限名称、接口要求及是否需要管理员同意，以当前平台页面和对应官方接口说明为准。不为本任务勾选全部权限。

### 3. 安全设置

核对实际页面提供的域名与 IP 配置项，按所选免登与 JSAPI 流程填写正式域名、必要的回调地址、服务端接口出口 IP。不能把首页网址、域名、OAuth 回调地址或服务器 IP 当作可以互换的配置值；也不能把仅用于浏览器 OAuth 的回调当成所有钉钉客户端免登的必需项。

JSAPI 鉴权并非每个接口都必需。需要鉴权的能力由服务端签名，前端不保管应用密钥；最终按实际使用的扫码等接口核对平台要求。

### 4. 网页应用

填写上述移动端与 PC 首页地址并保存。先在测试人员设备上验证 HTTPS、免登、权限和扫码，再扩大使用范围。

### 5. 版本管理与发布

创建版本，填写说明，先配置少量验收人员的可见/使用范围，按平台要求完成审核或发布。手机与 PC 钉钉分别从工作台验证应用入口及业务，验收后再对目标部门或全员开放。

### 6. 事件订阅

当前通讯录已有手动和定时同步基础。只有确定接收人员变化等推送事件时，再配置相应订阅及 Stream/HTTP 接收方案。发出工作通知本身不等于需要先实现所有事件订阅，不应为此随意填写一个未实现的回调地址。

## 四、现有系统还要改的地方

| 能力 | 当前代码情况 | 正式接入需要完成 |
| --- | --- | --- |
| 数据库 | 运行中仍使用 SQLite | MySQL 连接、建表与事务适配，原数据迁移和回归验证 |
| 钉钉 JSAPI | 登录页依赖 `window.dd`，没有显式加载 SDK | 加载并初始化官方 SDK，客户端识别，超时、失败与取消处理 |
| 工作台内免登 | 前端尝试调用免登，服务端目前使用用户 OAuth 换码接口 | 明确区分企业内免登码与 OAuth 授权码；按对应接口在服务端换取企业身份，再建立本系统会话 |
| 企业身份与权限 | 已有通讯录同步及 corpId/userId、员工 ID 和角色关联基础 | 联调企业范围、未关联员工、离职/停用、普通员工及审批人权限；不能按姓名自动授予权限 |
| 扫码 | 当前通用摄像头扫码 | 移动钉钉内接官方扫码能力，拿原文后进入现有解析/盘点逻辑；PC 提供编码输入及已有可用能力 |
| 通知 | 已写入待发送队列，没有发送器 | 工作通知发送、应用标识、接收人映射、去重、重试、失效待办取消及结果跟踪 |
| 单据直达 | 已有 `/?flow=单据ID` 打开单据基础 | 登录后保持目标单据，服务端验证查看与审批权限；通知链接的域名由服务端配置 |
| Excel 导出 | 浏览器和 Android 文件保存已实现 | 手机/PC 钉钉内的文件下载或打开方式需单独验收，不能沿用 APK 真机结论 |

依据官方免登说明，企业内部应用免登使用应用 access_token 和免登 code 获取企业 userid。结合当前前后端源码，现有免登码直接进入用户 OAuth 换码接口的实现需要调整，不能视为已经打通。

## 五、原二维码的使用边界

从资产应用内部的“扫码查询”或“盘点扫码”入口扫描，读取二维码原文并解析资产编码。保留原内容和原标签，不把供应商网址当作跳转目标。

在钉钉首页通用“扫一扫”中扫描旧网址，不保证自动进入新资产系统；现有供应商域名不归我们控制。实际使用指引应明确先打开资产应用，再使用应用内扫码。
