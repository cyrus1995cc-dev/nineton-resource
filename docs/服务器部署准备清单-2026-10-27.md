## 推荐申请配置

| 项目 | 配置 |
| --- | --- |
| 操作系统 | Ubuntu Server 24.04 LTS，x86_64，无桌面 |
| CPU | 2 核起步 |
| 内存 | 2 GB 起步，应用与 MySQL 同机；支持后续升配 |
| 磁盘 | 100 GB SSD，数据库使用持久化磁盘 |
| 网络 | 固定访问地址；需要公司外访问时提供公网入口 |
| 公网带宽 | 3～5 Mbps 起步，根据实际下载和并发情况调整 |
| 域名 | 公司现有域名的子域名即可 |
| HTTPS | 手机和浏览器信任的证书，配置续期 |
| 运行软件 | 编译后的 Go 程序、Nginx、systemd、CA 根证书；服务器无需 Node.js、npm 或 Go 编译器 |
| 数据库 | MySQL Community Server 8.4 LTS，部署时使用该系列最新安全补丁并验证兼容性 |
| 备份 | 独立备份位置、定时任务及恢复验证 |

这是当前资产规模的起步容量建议。本地已验证功能和事务并发，但未经目标 Linux 服务器 2 核 2G 容量压测。若公司已有 MySQL 服务，可共用数据库实例并创建独立库和专用账号，应用服务器规格另行评估。

## MySQL 要求

- 建议数据库名 `asset_system`，字符集 `utf8mb4`，业务表使用 InnoDB。
- 应用使用专用账号，限定连接来源及本库权限；建表升级与日常读写权限分别配置。
- 3306 端口仅允许应用服务器或本机访问，不向公网直接开放；数据库独立部署时使用内网连接，按公司要求配置 TLS。
- 约定数据库连接与系统操作时间使用 UTC，页面继续显示北京时间；原台账日期字符串按原值迁移。
- 定时做一致性备份，建议每日备份、保留 7～30 天，至少一份独立于数据库服务器存放；实际保留周期由公司确定。
- 由同事提供数据库主机、端口、库名、账号、访问范围及备份安排。密码不写入本文件或前端。

参考：[MySQL 官方 LTS 发布说明](https://docs.oracle.com/cd/E17952_01/mysql-8.4-en/mysql-releases.html)、[utf8mb4](https://docs.oracle.com/cd/E17952_01/mysql-8.4-en/charset-unicode-utf8mb4.html)、[InnoDB](https://docs.oracle.com/cd/E17952_01/mysql-8.4-en/innodb-introduction.html)。

## 网络与交接

- 对用户提供 HTTPS 443；80 按证书和跳转方案配置；SSH 管理端口仅允许运维来源。
- 应用 3000 端口仅供反向代理访问。
- 服务器可访问钉钉接口；部署安装依赖时提供下载通道。
- 域名同事只需域名、解析目标与证书信息，不需要整个项目。
- 最终部署再交付程序、网页构建文件、数据库迁移包和服务配置。

## 正式部署前需要完成的适配

1. 已实现 Go + MySQL 连接池、建表、索引、显式版本更新、事务和行锁；部署前用专用升级账号执行迁移工具。
2. 本地已验证 MySQL 审批原子回滚、重复处理、版本冲突、导入幂等和并发扫码；在正式配置下再次验收。
3. 从现有库导出并迁移资产、二维码原文与别名、人员、账号、历史记录及设置；密码哈希原样迁移，已有登录会话建议作废并重新登录。
4. 切换前备份，暂停旧库写入后执行最终迁移；校验记录数、关键字段、关联关系和金额，保留旧库用于回退，避免两边同时写入。
5. 回归资产查询、导入导出、流转审批、盘点与通讯录同步；完成 HTTPS、生产启动、管理员密码、登录保护、备份恢复和真机验证。
6. 将安卓 API 地址改为正式 HTTPS 地址后重新打包，现有资产二维码无需更换。钉钉登录和推送仍需企业联调。
