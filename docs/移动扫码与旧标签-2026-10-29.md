# 移动扫码与现有标签

## 员工使用路径

在钉钉工作台打开“九吨资产”，登录后进入“扫码查询”，使用“钉钉扫一扫”或“打开摄像头扫码”。手机浏览器及 Android 客户端使用同一套资产详情和操作界面，也支持手动输入标签上的资产编码。

扫码后默认显示名称、状态、资产编码、分类和型号；点“展开”查看位置、使用人、使用部门和公司。使用部门保留简短部门名。操作、维修、配件、其他记录分别查看；现有盘点、编辑及导入记录归入“其他记录”。当前没有配件业务数据，配件页签显示空状态。

底部默认是故障报修、交接他人、资产报失和更多，按账号权限和资产状态筛选。更多分员工操作、管理员操作，可设置最多三个底部快捷项，偏好仅保存于当前设备的当前账号。编辑资料保留原有版本校验；流转按钮把当前资产和类型带入既有申请流程，审批后才改变台账。

## 为什么旧码不能在钉钉首页直接进入九吨资产

二维码中的内容不会因为更换系统而改变。如果原标签编码的是公贝的网址，钉钉首页或其他通用扫一扫通常会打开该网址。九吨资产不能修改公贝域名的跳转，也不能拦截钉钉首页的扫码行为。

保留现有标签的办法：从九吨资产内扫码。本系统读取原文，提取末尾的资产编码，例如：

```
https://d.gongbeiyun.com/a/58b7d/57771/XSQ-0318
→ XSQ-0318
→ 查询九吨资产中的对应资产
```

整个查询不会请求或导航到原二维码中的网址，也不会在查询时改写资产或已有二维码。没有资产编码的短链或不透明标识不能猜测匹配，需输入标签上的资产编码。

如需钉钉首页直接扫码打开九吨资产，需换贴九吨资产的新网址标签，或由原公贝网址的管理方提供迁移跳转。现阶段无需批量换贴。

## 技术与验证边界

- 使用已安装的官方 `dingtalk-jsapi`，在手机钉钉环境调用 `biz.util.scan({ type: 'qrCode' })`，接收文本后走本站查询；普通浏览器不加载扫码桥。
- 原生桥失败或响应超时给出提示，保留 HTTPS 摄像头和手输备用入口。摄像头在关闭、成功识别、页面隐藏或组件卸载时释放。
- 扫码不扩大后端可见范围。普通员工仍只可访问本人、待审批相关或可领用资产；未关联员工身份的账号不能凭姓名操作旧资产。
- 单元测试覆盖旧网址解析、无效二维码、SDK返回/取消/超时及快捷项权限过滤。浏览器测试使用测试数据与模拟钉钉桥，检查布局、记录、权限、偏好保存、申请携带的资产及类型。
- 模拟桥通过不等于钉钉真机验收；真实手机的钉钉扫码及 Android 摄像头权限仍需设备验证。Android 已安装包需要重新构建、安装，才能使用新的内置前端。
- 本次更新扫码与详情，不新增钉钉 OA 审批实例或通知投递；这部分仍需单独完成企业应用凭据与审批接口联调。
