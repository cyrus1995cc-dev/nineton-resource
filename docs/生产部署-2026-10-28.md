2026-10-28 已部署源码提交 `9d6cff7` 对应的 Linux amd64 程序和前端静态文件。服务器为 Ubuntu 26.04 LTS，2 核、约 2 GiB 内存，已有 2 GiB 交换空间；安装 Nginx 1.28.3 和 MySQL 8.4.11。生产服务器无需 Node.js、npm 或 Go 编译器。

## 程序与配置位置

- 发布目录：`/opt/asset-system/releases/20261028-9d6cff7/`。
- 当前版本软链接：`/opt/asset-system/current`。
- 后端服务：`asset-system.service`，以无登录权限的 `asset-system` 用户运行，已开机自启。
- 后端环境配置：`/etc/asset-system.env`，仅 root 可读写。
- Nginx 站点：`/etc/nginx/sites-available/asset-system`，已链接到 `sites-enabled/`。
- TLS 证书：`/etc/asset-system/tls/fullchain.pem`；私钥：同目录 `privkey.pem`，仅 root 可读写。
- MySQL 小内存配置：`/etc/mysql/mysql.conf.d/asset-small.cnf`。
- 数据库：`asset_system`。业务账号 `asset_app` 仅有本库 SELECT、INSERT、UPDATE、DELETE 权限；建表升级使用独立账号。
- Go 只监听 `127.0.0.1:3000`，MySQL 只监听 `127.0.0.1:3306`；HTTPS 由 Nginx 对外提供，HTTP 自动跳转 HTTPS。

账号密码、数据库连接串、证书私钥和业务数据备份均未加入 Git。正式管理员使用独立生成的强密码，开发密码不能登录生产环境。完整凭据在服务器 root 专用目录保管，本地交接文件位于 Git 忽略的 `.data/` 内。

## 备份与恢复

`asset-system-backup.timer` 每天北京时间 03:15 至 03:20 触发，使用专用备份账号生成一致性压缩备份，保留约 14 天。备份目录为 `/var/backups/asset-system/`，备份账号配置为 `/etc/asset-mysql-backup.cnf`，权限 0600。

首份备份已在临时独立数据库恢复并核对 1,762 条资产、17 家公司和 1 个用户；验证库随后移除。首份备份也已下载至本地 `.data/production-offsite-20261028.sql.gz`。后续自动异机备份尚未配置，服务器上的每日备份不能代替持续异机副本。

常用检查：

```sh
systemctl status asset-system nginx mysql
journalctl -u asset-system -n 100 --no-pager
systemctl list-timers asset-system-backup.timer
systemctl start asset-system-backup.service
nginx -t
curl -fsS https://xz.vodayapp.com/api/health
```

恢复时先停止业务写入，在独立空库验证备份和记录数，再通过受控切换恢复生产；禁止直接覆盖仍在写入的生产库。版本更新先在新的发布目录校验 SHA256，再切换 `current` 并重启服务，保留旧版本供回退；有数据库结构变更时需先备份并使用升级账号执行迁移。
