# 九吨资产统一登录接入

依据用户提供的《九吨统一登录基础接入指南》和《九吨统一登录进阶接入指南》实现。生产域名为 `https://xz.vodayapp.com`，Issuer 为 `https://sso.nineton.cn`。这套应用凭据与钉钉企业应用凭据不同，不能混用。

## 平台登记与服务端配置

在统一登录平台为“九吨资产”单独登记机密 Web 客户端：

| 字段 | 配置 |
| --- | --- |
| 登录回调 | `https://xz.vodayapp.com/auth/oidc/callback`，逐字匹配 |
| 授权模式 | Authorization Code |
| PKCE | S256 |
| Scope | `openid profile email` |
| 首页 | `https://xz.vodayapp.com/` |
| Client ID / Secret | 平台为九吨资产签发的专用凭据 |

本地填写 `.data/sso-app.env`，该文件已加入忽略规则并限制到当前 Windows 用户与 SYSTEM。生产写入 root 0600 的 `/etc/asset-system.env`，重启后启用入口。未填写完整凭据时统一登录入口不启用，本地维护登录仍可使用。

```dotenv
SSO_ISSUER=https://sso.nineton.cn
SSO_CLIENT_ID=<本应用ID>
SSO_CLIENT_SECRET=<仅服务端保存>
SSO_REDIRECT_URI=https://xz.vodayapp.com/auth/oidc/callback
SSO_SCOPES="openid profile email"
SSO_PROVIDER_HINT=
```

`SSO_PROVIDER_HINT=dingtalk-nineton` 只在确认该身份源对本应用可用后填写。已通过该应用的登录配置响应确认此身份源启用，并验证带该参数时能进入钉钉授权页面，生产已配置该值。

## 登录与账号

- `GET /auth/login`：通过 Discovery 获取端点，生成服务端短期登录上下文，携带 state、nonce、PKCE S256。
- `GET /auth/oidc/callback`：浏览器上下文绑定、state 一次性消费；服务端换码，由官方 Go OIDC 客户端验证签名、Issuer、Audience、期限，另检查 nonce、多受众 azp、nbf 与签发时间。
- 使用 `(issuer, subject)` 唯一身份，不按姓名、邮箱或上游 isAdmin 合并、提权。
- 按用户最新要求，首次统一登录创建 `employee` 普通员工，无需逐个等待管理员授权。只能访问本人及所参与审批的资产、单据，以及可领用库存，不能管理账号、公司、组织或直接修改资产台账。上游 isAdmin 不赋予本系统管理权限。
- 用户本人已验证的唯一统一登录身份受控绑定到现有管理员账号，显示为“超级管理员”；其他人员默认普通员工。身份匹配使用 `(issuer, subject)`，不使用姓名识别管理员。
- 管理员可以在“系统设置”手工分配角色。要沿用员工身份、资产归属和原角色，先对照统一登录平台核实身份编号，再在“关联已有账号”中绑定；来源只能是未关联员工且没有申请/审批记录的普通员工或旧游客账号。绑定保留目标账号和业务记录，停用临时账号，撤销双方旧会话，保存审计。
- SSO 使用应用独立的 HttpOnly Cookie；HTTPS 使用 Secure、SameSite=Lax、`__Host-` 名称，无共享 Domain。上游 Token、授权码、Client Secret、PKCE verifier 不交给前端存储，不进入应用日志或数据库。
- 新会话空闲 30 分钟、绝对 8 小时到期。已有角色不会被重复登录覆盖；本地停用和通讯录授权范围缺失继续立即阻断访问。

## 退出和跨应用入口

`POST /api/auth/logout` 撤销本地会话并清除 Cookie，网页随后显示登录页。也提供 `POST /auth/logout`，完成来源校验后 303 返回 `/login`。退出可重复调用，只作用于九吨资产，不请求上游全局退出，不自动重新登录。

跨应用可使用 `https://xz.vodayapp.com/?silentSignin=1`，也可附加有效的 `flow` 单据编号。已登录时保留当前身份；未登录时仅尝试一次 `prompt=none`，取消、需要交互或失败后显示主动登录入口，不循环跳转。使用此入口前仍须由平台确认本客户端允许静默授权。返回地址只允许本站首页及数字单据编号。

进阶文档中的全局退出、后端注销通知、Refresh Token、项目组准入和组名称同步，本次未启用，也不预先调用管理接口。上游禁用并不会仅凭 JWT 验签立即撤销本应用会话；当前依赖本地停用和会话期限，若要求同步即时撤销，需要单独接入已确认的注销通知协议。

## 部署与验证

新增 `external_identities`、`session_policies` 表，仅新增表，不改写资产、公司或员工身份。升级前备份，执行 `asset-migrate` 建表，再切换服务和前端。旧 SQLite 导入会跳过源库不存在的新身份表，不迁移会话策略。

Nginx 必须代理 `/auth/` 到 Go；该位置关闭访问日志并设置 no-store/no-referrer，避免将回调授权码写入默认带查询串的访问日志。`/login` 由前端入口处理。

已通过隔离 MySQL 回归及真实 Go 服务配合模拟 OIDC 服务的浏览器验收：普通员工默认角色与数据隔离、PKCE、管理员受控绑定、Cookie 登录、角色保留、退出撤销、静默一次、已登录身份保持及手机布局。覆盖错误 state/nonce/iss/aud/azp、伪造签名、过期和未来令牌、重复回调、上下文过期、停用、空闲过期与 JWKS 轮换。

模拟身份服务验收不代表真实九吨统一登录已通过。2026-10-29 用户已提供本应用专用凭据，已写入本地受限配置文件与服务器环境，线上统一登录入口已启用。验证确认授权跳转携带正确 Client ID、精确回调地址、state、nonce、PKCE S256，并可经统一登录进入钉钉授权页面。随后用户已完成真实统一登录，服务端已建立经验证的外部身份与会话。按用户明确授权，将其唯一身份绑定到现有管理员账号，并将其他新用户的默认角色调整为普通员工。密钥不写入本文或 Git。

## 与钉钉联动的关系

统一登录提供身份，钉钉企业应用提供通讯录和 OA 审批。钉钉专用凭据仍在 `.data/dingtalk-app.env`，开通 API 权限并不等于已经配置凭据或实现审批推送。固定管理员审批、审批模板、发起 OA 实例和结果回传需要按实际企业应用继续联调；本次统一登录变更不会把现有通知队列标记成已发送。
