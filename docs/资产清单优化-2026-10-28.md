# 资产清单操作与布局优化

本轮同时调整清单的日常操作和视觉布局，前端仍在 `frontend/`，Go 后端仍在 `backend/`。部署继续使用编译后的 Go 程序和前端静态文件，运行环境无需 Node.js 或 npm。

## 使用方式

- 清单顶部按资产状态切换，显示当前查看范围内各状态的数量。
- 搜索可选择全部字段、资产编码、名称、序列号、使用人、部门、公司或型号。展开“筛选”可组合公司、分类、位置和部门，点击“应用筛选”后生效。已应用条件显示为可移除的标签。
- 电脑端固定资产编码和操作列，表格内可以纵向及横向滚动；点击表头排序，点击资产编码或行查看详情。状态合适时，行末提供领用、退库、交接等快捷入口。
- “显示列”选择需要的信息，“紧凑 / 舒适”调整行高，每页可选 20、50 或 100 项。列、密度和每页条数按账号保存在当前浏览器。
- 勾选后可跨页继续选择，最多 100 项。切换筛选或刷新会清空选择；翻页和排序保留选择。
- 批量工具栏只显示所有已选资产共同允许的流转类型。所有流转进入已有审批表单，审批通过后才更新台账；不直接批量改状态或归属。
- “导出资产”按已应用的筛选和排序导出全部结果；“导出所选”只导出勾选资产。两种导出均遵守账号查看权限，导出保留完整资产字段。
- 手机端使用资产卡片，展示公司、使用人、部门和位置，保留选择、详情和快捷操作。电脑显示列偏好不改变手机卡片内容。
- 首页继续保留资产总数、在用、空闲三项统计，不显示资产原值卡片。

## 接口与权限

`GET /api/assets` 和 `GET /api/exports/assets` 共用筛选与排序逻辑，新增 `searchField`、`company`、`department`、`category`、`sort`、`direction`。重复的 `code` 参数可限制到所选资产，最多 100 项。搜索和排序使用字段白名单，值通过 SQL 参数传入。

`GET /api/assets/options?scope=...` 返回当前账号及查看范围内的状态、公司、部门、分类、位置选项与数量。普通员工无法通过筛选选项或所选导出查看其他人员的资产。未关联员工身份的员工账号不能发起流转；只读角色不显示勾选及流转按钮。

## 验证

- 前端 8 个测试文件、23 项测试通过，Vue 类型检查及生产构建通过。
- 独立 MySQL `asset_system_test` 集成测试通过：组合筛选、搜索范围、稳定排序分页、排序参数校验、筛选导出一致性、所选导出和权限隔离。
- 浏览器使用独立测试库验证：跨页选择两项资产、导出所选、批量领用提交与审批后更新、筛选切换清空选择、筛选导出、显示列及密度保存、每页条数保存、100 项上限、只读与员工权限、手机详情。
- 现有预览数据用于只读视觉检查：1,762 条资产；1600×1000、1366×768 桌面及 390×844 手机视口，无页面横向溢出。
- 自动化 Chrome 访问本机偶发加载超时，完整交互测试通过 Node 转发真实本机 HTTP 响应完成；API 与数据库操作均由 Go 服务处理。
