# 自有资产管理系统

当前版本可在本地和局域网运行，包含：

- Web 资产看板和清单
- Excel 资产导入预览与确认
- 资产详情和流转时间线
- 二维码原文解析与资产编码查询
- Android 摄像头二维码扫描（ZXing）与手工输入兜底
- 领用、归还、借出、借出归还、调拨、交接、报修、报废、报失审批单据
- 多位指定审批人依次处理、驳回、撤回、评论和通知队列
- 按位置创建盘点任务、扫码登记和差异清单
- 盘点搜索、结果筛选、每页 20 项、进度和结束确认
- 实际登录人操作记录、重复扫码保护与保存失败回滚
- Android 友好的响应式页面基础
- 钉钉员工与部门同步、旧台账人员核对关联、我的资产
- 普通员工和指定审批人权限、账号角色调整与停用
- 编辑版本检查、导入防重与逐项履历、旧二维码原文保护

## 本地运行

```powershell
npm install --registry=https://registry.npmmirror.com
npm run import -- "C:\Users\张洋华\Downloads\资产清单2026-10-08.xlsx"
npm run verify:seed
npm run dev
```

浏览器打开终端显示的 Vite 地址（默认 `http://localhost:5173`，端口被占用时自动递增；当前本机为 `http://localhost:5174`）。开发 API 运行在 `http://localhost:3000`，Vite 会代理 `/api` 请求。

首次初始化使用 `admin / admin123`。新建数据库前可设置 `ASSET_ADMIN_PASSWORD`（也可以设置 `ASSET_ADMIN_USERNAME`）；环境变量不会更改已有账号密码。管理员可在“系统设置”创建账号、调整角色和停用账号；权限调整会撤销旧会话。未登录请求不会读取资产数据。密码重置和登录失败限流尚未实现。

## Android APK

安卓 APK 使用构建时的 `VITE_API_BASE_URL` 连接电脑上的 API。手机和电脑需要在同一局域网，先让后端监听 `0.0.0.0`，再把电脑局域网 IP 写入构建参数：

```powershell
$env:VITE_API_BASE_URL="http://192.168.1.100:3000"
npm run android:sync
Push-Location android
gradle assembleDebug
Pop-Location
```

生成文件：`android/app/build/outputs/apk/debug/app-debug.apk`。如果只是浏览器本地开发，不设置该变量即可，Vite 会继续代理 `/api` 到 `localhost:3000`。

钉钉企业通讯录同步及已有登录适配需要配置以下环境变量后重启后端：

```powershell
$env:DINGTALK_CLIENT_ID="你的AppKey"
$env:DINGTALK_CLIENT_SECRET="你的AppSecret"
$env:DINGTALK_CORP_ID="你的CorpId"
```

在钉钉后台为企业内部应用申请通讯录部门信息和部门成员读权限，并设置授权范围。在“系统设置 → 员工与部门”填写可访问的起始部门编号，执行“立即同步”。默认仅手动同步，可设为每 30 分钟、每小时、每 6 小时或每天同步。同步失败保留原通讯录；成功同步后未再读到的员工标为“授权范围待核对”，暂停关联账号访问，不直接认定离职。

首次同步建立普通员工账号，不生成可本地登录的密码。登录身份必须匹配已同步的本企业有效员工，不能仅凭姓名或 unionId 自动加入企业。旧台账只有姓名，需在“旧台账关联”结合部门、工号逐项核对，不会自动把重名人员关联。

现有钉钉登录适配调用 `https://api.dingtalk.com/v1.0/oauth2/userAccessToken` 和 `https://api.dingtalk.com/v1.0/contact/userinfo`，支持 `DINGTALK_TOKEN_URL`、`DINGTALK_USER_URL` 覆盖。Web、Android 和钉钉 H5 的授权入口、SDK 及企业应用配置仍须分别联调，不能仅配置上述变量就视为登录已打通。配置与使用详见 [员工通讯录与数据保护](docs/员工通讯录与数据保护-2026-10-15.md)。

## 数据和二维码

运行时数据库位于 `.data/asset.db`，不会提交到 Git。二维码只在系统内部解析为字符串，旧公贝云二维码的原文保存在 `qr_raw` 字段中，客户端不会自动打开该 URL。

已有非空二维码原文固定保留；后续扫到同一资产的不同内容单独记录别名，不覆盖原标签内容。手工输入编码查询不会覆盖原文；只读账号扫码只查询详情。扫码库在打开摄像头时加载，关闭扫描、离开页面或切到后台时释放相机。

### Excel 导入

管理员和资产管理员可上传 Excel，先核对新增、更新、无变化和异常行数量，再确认导入。异常行会显示行号与原因并跳过；空文本和空金额会保留原值，明确填写的 `0` 会覆盖金额。新资产的空金额按 `0` 保存。金额格式错误会阻止预览并提示需要修正的行。

已有资产的状态、使用人、部门、位置和领用日期变更须走审批；导入中包含这些变更的整行标为异常并跳过。新资产可在首次导入时填写初始归属。预览可展开普通资料差异，服务端保存原始预览及版本，30 分钟内由同一账号确认；预览后台账发生变化须重新预览。同一批次重复确认不会重复保存，每项普通资料更新都有操作者、前后值和批次履历。

### 盘点

1. 在“资产盘点”填写名称和位置范围，创建任务。
2. 输入或扫描现有二维码，可填写实盘位置与备注。实盘位置留空时按任务中的台账位置登记。
3. 按资产编码或名称搜索、按盘点结果筛选；明细每页 20 项。
4. 结束前弹窗提示剩余待盘数量，确认后把剩余项记为“未盘到”。结束后不能继续登记。

“实际已盘”只包含正常和位置差异；“差异”包含位置差异和未盘到。位置差异只记入本次盘点和资产履历；要调整资产使用人、部门或位置，提交交接或调拨审批申请。重复提交相同位置和备注不重复写履历。操作时间统一显示为北京时间。

## 流转审批与扫码详情

1. 管理员在“系统设置”指定其他管理员、资产管理员或审批人角色作为审批人；申请人不能审批自己的申请。只读账号可以查看单据和资产履历。
2. 在“资产流转”点击“发起申请”，选择 1 至 100 件资产，填写申请部门、目标信息和说明，按顺序指定 1 至 10 位审批人。
3. 审批人在“我的待办”逐一处理。全部通过后才更新台账；驳回和申请人撤回均保留完整记录。
4. 详情展示单号、申请人、部门、提交时资产快照、审批步骤、处理记录和评论。`/?flow=单据ID` 可在登录后直接打开单据。
5. 扫码详情展示基本信息和操作、维修、盘点、其他记录；新增流转及编辑记录显示字段前后变化。关联单号可点击打开审批单。底部报修、交接、报失和“更多”操作按账号权限及资产状态显示。

使用人、部门和位置通过审批流程变更；资料编辑仍支持名称、型号、分类、财务金额及备注等。已在审批中的资产不能再次申请；最终审批会核对提交时台账，发生变动则保留申请并提示撤回重填。批量资产变更和审批记录在同一事务中保存，失败会一起回滚。

多人编辑同一资产时校验版本号，后保存的人须重新核对，防止覆盖。普通员工与审批人可查看“我的资产”和可领用空闲库存，发起本人领用、归还、交接、报修或报失；姓名及部门由服务端按员工身份确定。审批人只处理分配给自己的步骤；可查看本人申请、接收和参与审批的单据。管理员、资产管理员和只读角色目前仍是全公司数据范围，按公司/部门细分管理范围尚未实现。

### 后续钉钉推送

审批待办和完结、驳回、撤回结果已写入 `notification_outbox`；单据详情可查看通知状态。推进到下一审批人或流程结束时，旧的未发待办会取消。当前没有启用发送器，队列不会自动发送消息；“待推送”表示已入库。

真实发送还需要企业应用权限、可访问的系统地址和企业联调。队列已保存已关联接收人的企业员工身份快照；unionId 不能直接视为工作通知的企业 userId。配置参数和发送重试策略将在联调时按官方接口确认。现有资产 Excel 只提供台账；未导出的原系统审批历史不会自动恢复或补造。
